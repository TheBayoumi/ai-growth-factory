# Expert audit of the rejected 1.3.0 output

## Verdict

The three files previously presented as verified canaries were not acceptable production canaries. They passed container/codec/level checks, but they were not subjected to adequate perceptual voice review or temporal-motion analysis. They are formally invalidated.

## Confirmed defects

### 1. Robotic, noisy narration

The narration was generated by `eSpeak`, not Qwen3-TTS. The script `scripts/generate_canaries.py` called `/usr/bin/espeak` directly and bypassed `build_reviewed_narration()`. Therefore:

- Qwen3-TTS did not generate the audio.
- Qwen2.5-Omni did not review the audio.
- Naturalness, timbre, buzz, phoneme quality, prosody and perceived noise were never evaluated.
- The existing DSP gate only measured level, clipping, silence, pace and DC offset. Those measurements cannot establish human-like speech quality.
- Loudness normalization made the synthetic formant/buzz artifacts more prominent rather than correcting them.

Calling these files voice-verified was incorrect.

### 2. Shaky hold-jump motion

The renderer used FFmpeg `zoompan` with a per-frame zoom increment of `0.00022`. At 720×1280, crop positions were quantized to whole pixels. The output therefore held nearly identical frames for several frames, then jumped by a pixel when the rounded crop coordinate changed.

The new temporal audit rejects the old files:

| Rejected file | Scene windows with hold-jump stutter |
|---|---:|
| dashboard-practical | 3 of 6 |
| kinetic-breaking | 2 of 6 |
| cinematic-contrarian | 3 of 6 |

Representative one-second windows contained 27–64% large frame jumps mixed with 27–64% near-identical frames. That is the visible stutter the user reported.

### 3. Misleading verification scope

The old video gate sampled only four isolated frames. It checked brightness, contrast and broad scene difference, but not consecutive-frame stability. A video can pass those checks while visibly shaking.

The local fixture script also selected source labels by scene number modulo source count. That did not prove the displayed publisher supported the specific scene claim.

### 4. Visual storytelling was not production-grade

Even without the stutter, the output was a procedural card slideshow rather than a polished editorial short:

- no real source-specific visual evidence;
- no claim-to-source mapping;
- generic motifs repeated across creative variants;
- captions duplicated body copy instead of using word-level emphasis;
- no validated transition language;
- the three “styles” changed treatment more than editorial structure.

## Corrective release 1.3.1

The corrective release makes the following changes:

1. Removes `zoompan` entirely from text-heavy editorial cards. Scenes are pixel-stable with semantic cuts.
2. Adds a consecutive-frame temporal gate that detects hold-jump motion.
3. Requires a production voice manifest proving Qwen3-TTS provenance.
4. Requires the final perceptual reviewer decision and local score thresholds before publication.
5. Rejects eSpeak, missing voice provenance and missing reviewer approval.
6. Renames the mechanical generator to `generate_visual_fixture.py` and requires an explicit opt-in flag.
7. Writes `NOT_A_PRODUCTION_CANARY.txt` beside every mechanical render fixture.
8. Adds `source_index` to every scene so the displayed publisher corresponds to the supporting source.
9. Keeps all output private until a real Modal T4 run completes with Qwen3-TTS and Qwen2.5-Omni.

## Current honest boundary

The stable renderer has been validated. The final voice has not been validated because this environment has no authenticated Modal GPU workspace and does not contain the Qwen3-TTS model weights. No replacement production canary should be shown or uploaded until that real model run occurs.
